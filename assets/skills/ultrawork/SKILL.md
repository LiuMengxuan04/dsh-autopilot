# Ultrawork

Maximize useful concurrency while keeping one accountable parent responsible for scope, integration, and verification.

## Anchor the run

1. Read repository instructions and inspect the working tree before delegation.
2. Read native Goal and `get_autopilot` state when available. Work against the exact authorized objective; never manufacture or enlarge a Goal or lease.
3. Convert the objective into acceptance criteria and a dependency graph.
4. Separate independent research or file ownership from integration-critical work.

## Orchestrate

When Autopilot is active, encode the graph with `autopilot_plan`. Use `autopilot_delegate` for one-shot batches, `autopilot_team_*` for continuable background workers, `autopilot_workflow_run` for a deployment-owned bounded pipeline, and `autopilot_ralph_*` for a fresh-agent repair loop over one ready leaf. Direct native subagent, workflow, Ralph, and scheduling tools remain denied because only the managed surfaces attribute children and charge the run budget. Outside Autopilot, use native DSH subagents for one or two bounded tasks and native `workflow` only when an explicitly requested larger pipeline benefits from it.

- Assign one owner to each mutable file or tightly coupled surface.
- Keep shared interfaces and integration points with the parent unless an explicit dependency orders the edits.
- Give every child a self-contained objective, permitted files, repository constraints, acceptance evidence, and a reporting format.
- Never ask children to weaken tests, bypass approval, expose secrets, or operate outside the user's scope.
- Treat child output as evidence to inspect, not as automatic truth.

Integrate completed work frequently. Re-read the working tree before applying a child's recommendation because all agents may share the workspace. Preserve unrelated user changes and stop parallel edits when ownership conflicts appear.

## Verify and finish

Run focused checks after each coherent increment, then the assembled end-to-end path. Use independent review subagents for materially risky changes. If an Autopilot lease is active, submit the complete evidence through `autopilot_verify`; otherwise use the native Goal completion policy. Never claim completion from a worker report, a green subset, or elapsed effort alone.

Pause for a missing human decision, exhausted authorization, destructive out-of-scope work, unavailable credentials, or an approval DSH requires. Report the exact remaining graph and recovery step instead of silently narrowing the objective.
